# 工作规范（用户要求，长期有效）

## 2026-10-24：问题必须解决，结果必须合格
1. **绕开没有解决的问题，永远不能算完成任务。**
2. **按时开工**：到了用户限定的时间，或者 usage 恢复了，就开始进程。
   - 无法开始（网络、显卡、上游数据没好）就挂任务等待；
   - 每 10–30 分钟确认一次能不能开始，不能干等。
3. **定时巡检**：进程开始以后，每 10–30 分钟检查一次进度、日志、资源和中间结果。
   - 不能只等进程结束后的反馈；
   - 发现异常（报错、卡住、中间结果明显不对）立即处理，不等跑完。
4. **失败或不理想要接着做**：反馈失败或结果不理想，不能写一条记录就算完。
   - 分析原因（是数据、代码、标签定义、评测，还是方法本身）；
   - 提出修正并实施，然后继续执行，直到结果满足事先登记的判定条件为止。
   - 修正如实披露为事后改动；改动来自看过测试集的错误分析时，换新的测试集重测；不降低门槛来"合格"。
