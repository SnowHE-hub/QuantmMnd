- T-017：v6 标签因缺 18 个交易日而 horizon 错位，但对 B **现有样本外评估**影响很小（63d IC 0.1051 → 0.1029；闸门 NAV +2.26% → +2.22%）。
  所以重训的主要价值**不是**修标签，而是：(1) 把 B 的预测延长到最新（原预测止于 2026-04-20，实时打分与 T-016 都需要）；

## 出结果前的修正（2026-10-11，任何评估运行之前）
- `eval_line_b_v6_1.py`：**原预测**的 NAV 改用原 v6 面板的 amihud 取滑点档。原因：两版 as_of 网格只有 110 个日期相同（T-017 报告 §3.1），
  用 v6_1 的 amihud 时原预测的大部分决策日取不到流动性，引擎会退到最保守的滑点档，使原预测的 NAV 被系统性压低。
  T-017 的 `line_b_gate_complete_prices.py` 本来就用 v6 面板，此修正与其一致。新预测（R / X / C / P）不受影响。

## 运行中发现的问题与修正（2026-10-11，P 方案尚无任何结果时）
- **P 方案训练失败**（第 3 折报 `Input X contains infinity`）。`inf_audit.py`：两个短周期因子含 ±inf——
  `sh_wq44_corr_high_rkvol_5` 95 个、`sh_wq3_rkopen_rkvol_10` 67 个（共 1,683,972 行，分布在 64–73 个截面）。
  统一训练（R / X / C，以及原 v6 种子）里，训练窗口只要含一个 inf，`RidgePredictor` 的该列均值 / 标准差就是 NaN，
  标准化后整列被填 0，即**这两个因子在几乎所有折里实际未被使用**（原有管线行为，不是本卡引入）；
  按板块训练时，某板块训练集恰好没有 inf 而测试截面有 inf，打分报错。
- **修正**：`train_line_b_v6_1.py` 增加 `--inf-to-nan`（±inf 视为缺失，输出加 `_infnan`）。
  板块判读改为比较**同一口径**下的 `P_infnan` 与 `C_infnan`（新脚本 `board_verdict.py`，IC 与区间方法同 `eval_line_b_v6_1.py`，规则不变）。
  原 C 方案的结果保留为主报告口径；`C_infnan` 与 C 的差异单独报告。
- 另：`eval_line_b_v6_1.py` 的"原预测同窗口 IC"只在两版网格重合的少数日期上计算（12d 4 个、63d 5 个截面），不可用；
  原预测在修正标签下的 IC 以 T-017 `b_ic_label_fix.json` 为准（63d 0.1029、12d 0.0692）。

## 结果（2026-10-11）
- 重训在 IC 量级上可复现（不是逐位相同）：R 方案 IC 63d 0.101 / 12d 0.066（原预测修正标签下 0.103 / 0.069）
- 连续样本外 C：63d 年化净超额 +4.74%（IR 0.61，16 次调仓）、12d +0.72%（IR 0.11）；均未过闸门
- 主线 B 板块专用 Ridge（预登记操作规则，P_infnan − C_infnan）：主板 +0.002、创业板 −0.018、科创板 −0.063 → **三个板块都未检测到增益**。
  原区间为独立自助法；时间块敏感性下创业板、科创板区间在至少一种块长下含 0，不能说"显著更差"（报告 §6）。
- T-016 重做（B 的 63d C 分数）：主比较 −5.29% → +7.78%（IR 0.44），分年 2025 −27% / 2026 +55%，闸门不通过；与 T-016 同样存在候选池不一致，只算回顾性探索
