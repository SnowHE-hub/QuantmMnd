# T-054 · 本机小模型做 A1 的"最后一段"：代码辅助 + 同一底座的多用途适配器

- 背景（T-041、T-051）：本机 Qwen3.5-9B 做 A1（财务事实）的召回一路从 34% 提到 90%。这些提升都来自代码，不是更长的提示词：
  | 版本 | 做法 | 召回 |
  |---|---|---|
  | v1.2 | 工具循环 | 34% |
  | X7b | 单次调用 | 51% |
  | v3 | 可读金额 + 完整性检查 | 65% |
  | v3.1 | 去掉引文字段 | 90% |
  - 但离降级后端的标准（召回差 ≤ 5pp、有问题声明差 ≤ 2pp）还差一段：L31 召回 90.3%、有问题声明 9.1%，DeepSeek 是 99.2%、0.0%。
- 用户 2026-10-24 的要求：
  - "研究补齐最后一段"；
  - 借鉴 capstone 的做法：同一个 2B 底座，微调出不同用途的模型（VT 判别、固定格式 JSON 生成）。
- 分支 `t/035-line-a-v2-p0`，不推送。

## 登记（2026-10-24 12:4x，在任何实现和运行之前）

### 1. L31 剩下的错误（留出集 3，看过之后才写这一节，所以评测换新的留出集 4）
- 有问题声明 9.1% 的主要来源：数值和字段不对应、数量级错误、计算声明的公式或输入不全。

### 4. D2 的蒸馏数据（与留出集 4 无关）
- 案例：
  - 2021-01 到 2026-08 每月第二个交易日取一个时点，去掉与开发集、留出集 1–4 相差 20 天以内的时点；
  - 每个时点 10 个案例，种子 20261030，约 600 个案例。
- 教师：DeepSeek v3.1 单次调用（生产口径）。
- 目标：教师输出**只保留通过代码校验的声明**（verified / minor_mismatch）。
  - 整个案例没有合格声明的就丢弃；
  - 引用了紧凑视图里没有的记录的声明也丢弃。
- 输入：与 D2 推理时同一套代码辅助的任务文本。
- 切分：按时点 90 / 10 分训练和开发；开发集用来选 S2–S4 的组合和早停，不碰留出集 4。
- 训练：Qwen3.5-2B（本机 `D:/RAGScope_Runtime/models/Qwen3.5-2B`，revision 15852e8c）。
  - QLoRA：4-bit 底座，LoRA r16 / α32，学习率 1e-4，2 个 epoch，单卡 8 GB；
  - 只对输出部分计损失。

### 5. 同一底座的第二个适配器：VT 判别（公告分类，X4-VT2）
- 同一个 2B 底座，另训一个 LoRA。
- VT 协议：
  - 输入"标题 + 一个类别的定义（指南 v2.1）"，读模型下一个 token 是"是"的概率；
  - 训练用 x4_v22 的 DeepSeek 标签（指南 v2.1）：每条标题对每个类别生成一对；
  - 正例全取，负例按"同标题的其他类别 + 难负例"抽样，总量约 8 万对。
- 阈值：在 x4_v22 校准集上按 F1 选。
- 评测：金标准 v2 和 gold-hard，与 MacBERT v2.2（已采用）比较。
  - **采用条件**：gold-hard F1 比 v2.2 高 0.02 以上，金标准 v2 F1 不低 0.005 以上，严重类型召回不低于 v2.2。
  - 不满足就只作为研究结果，不替换 v2.2。
- 部署形态：一个底座同时加载 A1 适配器和 VT 适配器，按任务切换（peft 多适配器），不需要两份底座权重。

### 6. 判定
- 本机后端作为 A1 降级后端（DeepSeek 不可用时）：对 R 组满足三条才算通过：召回差 ≤ 5pp、有问题声明差 ≤ 2pp、弃答 ≤ 10%。
  - S1–S4、D2 逐组判定，选通过的里面最便宜的（2B < 9B）。
- 每一级代码辅助的效果，只作描述；不做多重比较校正，结论里写明。
