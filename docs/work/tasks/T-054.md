# T-054 · 本机小模型做 A1 的"最后一段"：代码辅助 + 同一底座的多用途适配器

- 背景（T-041、T-051）：本机 Qwen3.5-9B 做 A1（财务事实）的召回一路从 34% 提到 90%。这些提升都来自代码，不是更长的提示词：
  | 版本 | 做法 | 召回 |
  |---|---|---|
  | v1.2 | 工具循环 | 34% |
  | X7b | 单次调用 | 51% |
  | v3 | 可读金额 + 完整性检查 | 65% |
  | v3.1 | 去掉引文字段 | 90% |
  - 但离降级后端的标准（召回差 ≤ 5pp、有问题声明差 ≤ 2pp）还差一段：L31 召回 90.3%、有问题声明 9.1%，DeepSeek 是 99.2%、0.0%。
- 用户 2026-10-24 的要求：
  - "研究补齐最后一段"；
  - 借鉴 capstone 的做法：同一个 2B 底座，微调出不同用途的模型（VT 判别、固定格式 JSON 生成）。
- 分支 `t/035-line-a-v2-p0`，不推送。

### 5. 同一底座的第二个适配器：VT 判别（公告分类，X4-VT2）
- 同一个 2B 底座，另训一个 LoRA。
- VT 协议：
  - 输入"标题 + 一个类别的定义（指南 v2.1）"，读模型下一个 token 是"是"的概率；
  - 训练用 x4_v22 的 DeepSeek 标签（指南 v2.1）：每条标题对每个类别生成一对；
  - 正例全取，负例按"同标题的其他类别 + 难负例"抽样，总量约 8 万对。
- 阈值：在 x4_v22 校准集上按 F1 选。
- 评测：金标准 v2 和 gold-hard，与 MacBERT v2.2（已采用）比较。
  - **采用条件**：gold-hard F1 比 v2.2 高 0.02 以上，金标准 v2 F1 不低 0.005 以上，严重类型召回不低于 v2.2。
  - 不满足就只作为研究结果，不替换 v2.2。
- 部署形态：一个底座同时加载 A1 适配器和 VT 适配器，按任务切换（peft 多适配器），不需要两份底座权重。

### S5：数字归代码（`small_aids.render_a1`，在任何留出集 5 结果之前写下）
- 思路：模型负责"选哪些事实、写哪些计算和推断"，**数字全部由代码给出或改写**：
  1. 必须覆盖的事实（收入、归母净利润两期，预告类型，审计意见）和两项同比增速，由代码直接写进结果（k1…），任务里告诉模型不用再写；模型写了同一个事实就保留模型那条；
  2. 模型的 reported_fact：value 改成所引记录的原值，正文里的金额按记录重写（只改相差 0.5% 以内或正好差 10^k 的写法）；
  3. 计算器：模型写 formula，代码求值，把正文里**唯一**的那个同类数字（百分数或金额）改成计算结果；有几个就不动，照常校验；
     单位 %、两个输入是同一字段相隔一年的两期时，公式统一成 (新−旧)/|旧|×100（防止比值当增速）。
- 组合：S5 = compact + repair + render（不加 prefill，render 已经包含）；完整性补充轮关掉（必须覆盖的事实由代码写入）。

- 登记的 5 条：
  1. 召回差 −4.2pp（S5 更高），95% 区间 [−6.7, −2.1] → 通过；
  2. 全部声明有问题比例差 +0.70pp，区间 [0.15, 1.42] → 通过；
  3. 弃答 0% → 通过；
  4. 模型自己写的声明有问题比例差 +1.00pp，区间 [0.17, **2.14**] → 点估计通过（登记按点估计）；区间上界略超 2pp，如实记录；
  5. 模型自己写的声明数 11.9 ≥ 9.1（R 的非必须覆盖声明数的一半）→ 按登记口径通过。
- **登记之外的严格口径（判定后才想到，作为事后补充，不改判定）**：
  模型把代码给的必须覆盖事实大多照抄进了自己的声明（代码补写的平均只有 0 条，代码重算同比的 2 条另计），
  第 5 条把这些也算成"模型写的"。扣掉引用必须覆盖事实的声明后，模型自己补充的声明只有 **6.95 条 / 案例**，
  低于 9.1 → **按严格口径不通过**；这些补充声明的有问题比例 1.44%（合并口径）。
- **结论**：
  - 本机 9B + 代码作为 A1 的**降级后端可用**：必须覆盖的事实全对、数字可信；
  - 但**覆盖面只有 DeepSeek 的约 37%**（补充事实 7 条 vs 约 19 条），不能替代日常的 DeepSeek A1。
- **原因分析**：代码接手数字之后，9B 剩下的是"选什么事实写"。它倾向于只写任务里点名的几类，现金流、负债、预告差异各写一两条就停。
