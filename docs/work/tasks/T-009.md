## 背景（[代码]，见 `docs/work/acceptance/T-001.md`）
- T-001 恢复了 `detect_categorical_cols` / `encode_categorical_codes`，但 `LGBMRankerModel.fit` 从未接受 `categorical_feature`，
  因此去掉了该参数：行业（110 类）、地区（32 类）被当作**有序数值**分裂，与 `scripts/run_wf_full_v1.py:53-55`、`:503-505` 记录的原设计不符。
- `scripts/train_lgbm_12d.py:99` 仍向 `fit` 传 `categorical_feature=`，运行即 `TypeError`。
- 编码按出现顺序 factorize：fit 与 score 必须传入同一张 panel 才一致。

## 改动
- `factor_model.categorical_categories`：fit 时保存的取值字典（按字符串排序）；
  `encode_categorical_codes(..., categories=None)`：给字典时按字典编码，字典外 / 缺失 → -1；不给时行为不变。
  `build_lgbm_arrays(..., categories=None)`：透传。
- `LGBMRankerModel.fit(..., categorical_feature=None)`：透传给 `lgb.LGBMRanker.fit`；名字不在 `feature_names` 中时报错。
- `wf_gate.LGBMPredictor`：fit 保存字典并以原生类别特征训练；score 复用字典；docstring 改为与实现一致。
