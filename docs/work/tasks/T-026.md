# T-026 · RidgePredictor 把 ±inf 当缺失（不再整列清零）

- 状态：implemented
- 建卡与实现：Claude Code 桌面版，2026-10-11（升级方案盘点"接下来的计划"第 4 项；用户："其他按你推荐的继续推进"）
- 分支：`t/026-ridge-inf`（基于 `main` a0e63ba）；验收：Codex

## 问题 `[实测]`（T-018 发现，`docs/work/evidence/T-018/inf_audit*.json`）
- 主线 B 的 `scripts/bakeoff/p3b_tabular.py::RidgePredictor` 用训练集均值 / 标准差标准化，再把 NaN 填 0。
- 两个短周期因子在 v6_1 面板里各有几十个 ±inf（63d 种子：95 个和 67 个）。一列里只要有一个 inf，该列均值或标准差就是 inf / NaN，
  标准化后整列为 NaN，再被填 0：**这个因子在训练和打分里实际都没被使用**。
- T-018 当时没改公共代码，只在训练脚本里加了 `--inf-to-nan` 开关（先把 ±inf 换成 NaN）。同一协议下 63d 种子：
  不处理 +4.74%/年（IR 0.61）→ 处理后 +5.03%/年（IR 0.64）。

## 改动
- `RidgePredictor.fit` / `score`：取数值特征后先把 ±inf 换成 NaN（与 `--inf-to-nan` 等价），其余不变。
- 测试 `tests/test_ridge_predictor_inf.py`（3 个）：训练集有 inf 时该列系数不为 0；结果与"先把 inf 换成 NaN"逐值相同；没有 inf 时与原公式相同。

## 影响范围
- 用到 `RidgePredictor` 的脚本：`scripts/bakeoff/p3b_tabular.py`、`scripts/survivorship/p4c_train_v6.py`、`scripts/survivorship/p63_3_train_v6.py`，
  以及 T-018 / T-022 / T-023 的训练脚本。**以后重训的结果会变**（只要特征里有 ±inf）；已有的预测文件不重算、不覆盖。
- T-018 训练脚本的 `--inf-to-nan` 开关变成多余，保留不删（打开与否结果相同）。
- 生产日更不使用 `RidgePredictor`（主线 A 用 LGBM），不影响定时任务。

## 验证
- 用修复后的代码、按 T-018 方案 C、**不加** `--inf-to-nan` 重训 63d 种子，结果应与已有的 `ridge_63d_v6_1_C_infnan.parquet` 逐值相同。
- **结果（2026-10-11 `[实测]`）**：重训 9 折约 20 分钟；1,000,377 行预测与 `C_infnan` 一一对应（无多无少），最大绝对差 **0.0**。
  脚本 `~/c3_scratch/run_t026_verify.sh`（训练脚本取自 T-018 证据目录，输出在 scratch，不写数据目录）。
