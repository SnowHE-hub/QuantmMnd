## 现象与根因 `[实测]` `[代码]`
- 定时任务每个交易日 16:30 跑 `scripts/daily_update.py`。Step 7a（6-Agent 分析）读 `data/paper_trading/strategy_config_v2.json`：
  `agent_mode = "full"`、`ollama_model = "qwen2.5:7b"`，探测 `http://localhost:11434/api/tags`。
- WSL 里 ollama 已安装（`/usr/local/bin/ollama`，系统服务 `ollama.service`），但服务是 **disabled / inactive**，
  所以每次都是 `[Step7a] Ollama 不可用，full → fast 降级`（例：`logs/quantmind_2026-10-09.log`），实际跑的是规则版。
- full 模式下各 Agent 通过 `OllamaReActClient` 调 `/api/chat`（ReAct 工具调用），模型名在代码里默认 `qwen2.5:7b`。
  **qwen2.5:7b 必须保留**（`/usr/share/ollama/.ollama/models`）；另两个旧模型（deepseek-r1:7b、gemma4:12b）不被使用。
- 冷启动：2026-10-11 用临时（非 sudo）ollama 进程实测，GPU 识别约 26 秒，第一次 `/api/chat` 在 120 秒内没有返回
  （当时 WSL 内存被 T-018 训练占用约 8 GB，属偏慢情形）；Agent 单次调用超时 60 秒，冷启动时首批调用会降级。
  内存空闲时复测（15:51）：服务就绪 21 秒、模型加载 20 秒、显存 4.6 GB；单票 full 模式 6-Agent 52 秒、14 次 `/api/chat`，无降级。
  即正常情况下冷启动不超过 60 秒；预热是为机器忙时（与训练 / 其他任务并发）兜底。

## 改动
1. `quantmind/agents/ollama_client.py`：新增 `OllamaReActClient.warm_up(model, base_url, timeout=300, keep_alive="30m")`——
   空 prompt 的 `/api/generate` 只加载模型；返回 (成功, 耗时, 说明)，不抛异常。
2. `scripts/daily_update.py` Step 7a：探测可用后、开始分析前先预热（超时取 `ollama_warmup_timeout`，默认 300 秒）。
   预热成功 → 记录耗时；返回 404（模型未安装）→ 明确降级为 fast 并写明原因；其他失败 → 仍按 full 运行并告警。
   `agent_stats.json` 增加 `ollama_warmup` 字段，降级与否可在产物里直接看到。
3. 测试：`tests/test_ollama_agent.py` 新增 3 个（成功、404、超时）；该文件 34 passed。ruff：两份源文件的 27 条告警均为原有，无新增。

## 需要用户执行（一次即可，持久生效）
```bash
sudo systemctl enable --now ollama
```
服务以 `ollama` 用户运行、开机自启；模型只在被调用时加载进显存，默认空闲 5 分钟后释放（预热设 30 分钟）。
**注意**：不要删除 qwen2.5:7b。
