## report_rc（卖方盈利预测）中转数据
- 背景：官方接口限每天 10 次，按现在的速度补完要 4–5 个月。用户 2026-10-21 在咸鱼买了第三方中转（有效期 7 天），要求试用。
- 来源：`http://tus.sxdata.top/tu_share/`，不是 Tushare 官方。
  - 是 **HTTP 明文**：token 和查询参数在网络上不加密。查询内容只有股票代码和日期，不含账户和持仓信息；token 是一次性购买、7 天有效。
  - token 只存在 `~/.config/quantmind/relay_token`（权限 600），不进代码、日志或提交。
- 中转方的限制（试出来的）：
  - report_rc 必须带 ts_code；
  - 单次日期区间约一年以内，超了报 `date_range_too_large`；
  - 频率超限报 `rate_limited`，建议等 30 秒；
  - `upstream_pool_exhausted`（中转方的上游账号池暂时用完）：2026-10-21 晚上实测，report_rc 有 30–70% 的请求这样失败，每次失败约 10 秒；同一时间 `daily` 6/6 成功。成功和失败交替出现，所以只等 4 秒就重试；
  - 多个 ts_code 用逗号拼接返回 0 行，不能批量。
- 拉取：`scripts/data_pipeline/fetch_report_rc_relay.py --by-ticker`。
  - 从 2019-01-01 开始（官方已有 2018-10-01～2019-04-13）；每只股票按自然年分段，共 38,267 段，按段做检查点；
  - 顺序（第一版"前 300 只股票的 2018–2019 段 + 按年份从近到远"在做任何比对之前就改了（只有几次探测请求，看过行数，没有和官方比过），原因是速度只有预期的几分之一）：
    1. 校验集：官方 2019 年窗口里有记录的股票随机抽 200 只、没有记录的抽 50 只（种子 20261021），先拉它们的 2019 段；
    2. 其余分三层：每年按年初总市值排名（年内上市的按上市后第一个交易日），1–1500 名、1501–3000 名、其余；每层内按年份从近到远。
  - 这样 7 天内拉不完时，已拉到的范围是"每年市值前 N 名"，各年口径一致；下游必须区分"拉过、没有研报"（empty）和"没拉"（不在检查点里）。
- 存放：`data/lake/events_relay/report_rc/`，与官方的 `data/lake/events/` 完全分开，附 `_provenance.json` 和 `by_ticker/_validation_tickers.json`。

### 验收规则（2026-10-21 登记，在看到校验结果之前）
