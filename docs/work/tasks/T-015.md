## 背景
- [实测] lake 的 daily / adj_factor / daily_basic 止于 2026-05-11，并缺 18 个真实交易日；index_daily、north_bound、margin 止于 5 月底至 6 月初；
  财报类（fina_indicator / income / balancesheet / cashflow）止于 2026-05～06。
- [代码] 根因链：`step2_download_prices.py` 把失败日标成完成（T-012）→ `alpha_prices_panel.parquet` 缺 18 天 →
  `quantmind.data.lake.load_trading_calendar()` 由该文件反推日历 → `backfill_tushare.py` / `p1_pull.py` 按该日历决定拉哪些日期 → 全部 lake 序列缺同样 18 天。

## 做法与约束
1. 交易日历直接取 Tushare `trade_cal`（SSE，is_open=1）→ 新文件 `data/lake/trade_cal_sse.parquet`
2. 行情类：`scripts/data_pipeline/update_lake_latest.py`。目标日期 = 日历 ∩ 区间 − lake 已有日期；只新增日期；新行对齐现有列与类型；
   每张表首次写入前备份到 `data/lake/_backup_20261010/`；交易日空表 = 失败（不写入、下次重试）
3. 财报类：`scripts/data_pipeline/update_fundamentals_latest.py`。按代码增量拉 2026 年以来公告的记录，主键 `(ts_code, end_date, ann_date)` 已存在的保留旧值
4. 派生价格表：`scripts/data_pipeline/build_price_panels.py` **生成新文件**，不覆盖原文件（`p2_build_v6.py` 对 v5 价格文件有 md5 守卫）：
   `data/raw/alpha_prices_panel_v6_20261009.parquet`（后复权，同 v6 口径）、`data/raw/alpha_prices_panel_20261009.parquet`（1374 票池，前复权，同 v5 口径）
5. 面板：`data/panel/alpha_panel_v4_2.parquet`（T-003 的 `--relabel-from`，不保留 v4 标签掩码、价格用到最新快照）
6. 不改任何现有代码的默认数据路径；切换默认文件需另行决定（见报告"后续"）

- 处置：发现时财报下载仍在后台写 lake（1,000 / 5,243），**先停止**（写入是 tmp + replace，中途停止不损坏文件）。

  ann_date 晚于 `--end` 的记录不写入（固定截止日）。
- 修复：`--repair-from-backup data/lake/_backup_20261010`——备份旧表 + 当前表中主键不在备份里的行（主键里的字面 "None" 视为 null）。
