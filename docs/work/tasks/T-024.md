## 对比方法（脚本 `docs/work/evidence/T-024/ab_agent_models.py`，只读，不写生产产物）
- 输入：生产特征 `data/features/alpha_2026-09-30.parquet`；10 只票 = 流通市值最大 5 只 + 其余随机 5 只（种子 0）。
- 每个模型先预热，再对每只票依次跑 5 个辩论 Agent（估值 / 动量 / 质量 / 情绪 / 风险），mode = full，共 2 × 50 次。
- 上下文里新闻、研报为空，`lgbm_score` 为 0（与日更时 Agent 能拿到的信息不完全相同；两模型输入一致）。
- 记录：是否真的走了 LLM（否则为降级到规则）、工具调用次数、耗时、信号、置信度、摘要（截前 120 字）。

## 结果（`docs/work/evidence/T-024/ab/`）
| | qwen2.5:7b | qwen3.5:9b |
|---|---:|---:|
| 走 LLM 的比例（不降级） | 50/50 | 50/50 |
| 报错 | 0 | 0 |
| 单次 Agent 平均耗时 | 8.1 秒 | 15.2 秒 |
| 平均工具调用 | 2.84 | 2.52 |
| 信号：看空 / 中性 / 看多（按符号） | 18 / 24 / 8 | 23 / 11 / 16 |
| 信号样本标准差（ddof=1，按 `ab_rows.csv` 重算） | 0.31（0.3147） | 0.52（0.5164） |
| 显存占用（ollama ps） | 约 4.6 GB，全部在 GPU | 6.3 GB，23% 放在 CPU |

- 两模型信号的相关系数 **0.04**；方向一致率 38%（|信号| ≤ 0.1 记为中性）；平均绝对差 0.45。
- 分 Agent：风险 Agent 给出非零信号的比例 7b 为 10%、9b 为 100%；动量 Agent 50% vs 90%；情绪 Agent 两者几乎都为 0（输入里没有新闻）。
- 两者都没有输出思考段落。
- 个例：贵州茅台估值 Agent，7b 的摘要写"PE_TTM 远高于行业平均……表明相对便宜"（前后矛盾）；9b 给 +1.0、置信度 0.82。只是个例，不作统计结论。

- 口径说明：上表"看空 / 中性 / 看多"按信号符号计（0 记中性）；"方向一致率 38%"按 |信号| ≤ 0.1 记中性。两个口径不同，不能混用。

## 结论与建议
1. **本批观察：两个模型都没有降级**（预热后 50/50 走 LLM）。这次对比每个模型都先预热，没有"不预热"的对照组，
   所以不能据此说"预热解决了降级"；生产日志里此前的降级原因是服务未启动（T-021）。
2. **没有证据表明 9b 的判断更准**：两者结论几乎不相关，说明换模型会大幅改变每日报告的内容；但这次没有"正确答案"可对照，
   9b 更敢下结论（中性更少、信号更分散），不等于更对。
3. **代价**：9b 慢约 1.9 倍（按日更 Top-10 估算，6-Agent 环节从约 9 分钟变成约 17 分钟）；8 GB 显存放不下，23% 跑在 CPU；与 Bonsai 27B 更难错开。
4. **建议**：生产先**维持 qwen2.5:7b**（不改配置）。换模型现在只需改 `strategy_config_v2.json` 的 `ollama_model` 一项。
   要判断哪个更好，需要有前瞻收益可对照的评估：例如两模型影子并行若干周，用 Agent 信号对随后 20 日收益算 IC；
   据代码检查，Step 7a 的产出写入报告、`strategies.json` 和数据库 `agent_analysis`，不进入推荐名单，所以这项评估优先级不高。

## 限制
- 只有 10 只票、一个日期、每组合跑一次（LLM 有随机性，未重复）。
- 输入没有新闻和研报（情绪 Agent 无信息），与日更实际输入不同。
