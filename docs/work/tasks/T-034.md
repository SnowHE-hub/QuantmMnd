## 分步

### A. 第 18 折模型包（现在做；GPU）
第 18 折是 20d 最后一折：切点 2026-07-01，负责的预测日到 (C₁₉ + E] 为止。下一个季度切点之前，前瞻打分都由它负责。

| 族 | 已选配置（`ledger/k18_selected.json`） | 做法 | 核对（事先写定） |
|---|---|---|---|
| XGBoost | rank，深度 6，850 轮 | 加载 `k18_s{0..4}.ubj` | 对第 18 折预测日重新预测，与 `k18_s*.npy` 的最大绝对差 = 0 |
| TabM | config 1，3 个 epoch | 加载 `ckpt/k18_final_s{0..4}.pt`；按 `dl.fit_norm` 重算该折的归一化统计 | 最大绝对差 ≤ 1e-3（GPU 推理的浮点误差），且相关 ≥ 0.9999 |
| 序列融合 | config 2，10 个 epoch | 同上 | 同上 |
| CatBoost | YetiRank，深度 8，1400 轮 | **按同一配置、种子 0–4、隔日偏移（种子 % 2）重训**，并保存 `.cbm` | CatBoost GPU 不保证逐位确定：报告与 `k18_s*.npy` 的相关和最大差；相关 < 0.99 时单独标注 |

模型包输出到 `data/gpu_v1/forward_models/20d_fold18/`：
- 模型文件；
- 配置；
- 归一化统计；
- 特征列表；
- 每个文件的 sha256。

组成 ENS 后，对第 18 折预测日重新打分，与 `preds/<族>_20d/fold_18.parquet` 合成的 ENS 比较，报相关和最大差。

### B. 前瞻数据刷新（先设计，后实现）
现有构建器的输入写死在 2026-10-09 的文件上，按月输出，已存在的月份会跳过。要做的是：
1. 用 `update_lake_latest.py`、`update_fundamentals_latest.py`、`download_events.py`（新的结束日期）把数据补到最新；
2. 用 `build_price_panels.py` 生成新的价格面板；
3. 新建 `data/gpu_v1/panel_fwd/`，只对新日期用同一套构建函数重算；
4. **重叠期一致性检查**：在 2026-09 的已有日期上，重算结果必须与冻结面板逐值一致；
5. Ridge C 的 v6_1 周频面板也需要同样的延伸，前瞻对照要用。

是否接定时任务：**由用户决定**，默认手动运行。
