# T-051 · A1 Harness v3：可读金额、完整性检查、文字字段核对；留出集 2 上重测 DeepSeek 与本机 9B

- 起因（2026-10-23 晚）：
  - X7 v1.2：本机 9B 工具循环，召回 34.3%；
  - X7b：本机 9B 单次调用，前 14 个案例召回 46.9%。
  - 错误集中在三类：
    1. 元 → 亿元换算错一个数量级（543.34 亿 vs 54.33 亿）；
    2. 漏写上年同期的营收和归母净利润（14 个案例里漏 12–13 次）；
    3. 审计意见、业绩预告类型这类文字字段，模型用 value = 1.0 加字段名引用，校验器核不了。
  - DeepSeek 也有第 2 类问题：留出集上最常漏的是"最近一次业绩预告的类型"。
- 分支：`t/035-line-a-v2-p0`，不推送。

## 登记（2026-10-23 22:5x，在实现和运行之前）

### Harness v3 的三处改动
1. **可读金额**：工具返回的金额字段另附 `_display`（例如 `"revenue": "54.33亿元"`），由代码换算。模型可以直接照抄，不用自己换算单位。
2. **完整性检查**（只针对 A1，代码实现）：角色输出通过 Schema 校验之后，代码检查 A1 提示词 v2 规定"必须覆盖"的几项有没有写到：
   - 最新报告期和上年同期的营业收入、归母净利润（引用对应期间的利润表记录）；
   - as_of 前 120 天内的业绩预告类型（工具返回了预告才要求）；
   - 最近一份年报的审计意见（工具返回了审计记录才要求）。
   - 缺了就把缺失清单发回去，让模型补一次、输出完整 JSON。只补一次，补完不再检查；
   - 只检查"有没有写"，不检查数值，数值仍由校验器核对。
3. **文字字段核对**（校验器）：引用的字段在记录里是文字（如 audit_result、forecast 的 type）时，核对声明正文或引文里有没有出现记录里的这段文字。

### 评测：A1 留出集 2（新）
- 原来的留出集已经在 X7、X8、X10 里用过很多次，这次的改动又是看着它的错误设计的，所以另抽一个新集合：
  - 种子 20261026；
  - 时点 2025-09-10、2025-11-10、2026-05-11、2026-09-10，与开发集、留出集都不重叠；
  - 每个时点 10 个案例，共 40 个；
  - 同一份标准事实和打分函数。
- 三组：

  | 组 | 后端 | Harness |
  |---|---|---|
  | B | DeepSeek | 单次调用（当前默认） |
  | V | DeepSeek | 单次调用 + v3 |
  | L | 本机 9B | 单次调用 + v3，关闭思考，32K，约束解码 |

### 判定
- **v3 用于 DeepSeek**：V 的召回不低于 B 1 个百分点以上，且有问题声明不高于 B 0.5 个百分点以上。
- **本机 9B 作为 A1 的降级后端**（DeepSeek 不可用时，例如校园网）：
  - L 的召回不低于 V 5 个百分点以上；
  - 有问题声明不高于 V 2 个百分点以上；
  - 弃答 ≤ 10%。
- 先跑 L（不需要外网）；B、V 等网络恢复后跑。
