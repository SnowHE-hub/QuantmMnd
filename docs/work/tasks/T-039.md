## 结论
1. 问题是真的。lake 的 income / balancesheet / cashflow 里，有 1.4% / 1.6% / 0.8% 的行是**后来才公布的版本，却挂在原始公告日下**（前视）。按公司-报告期合并三张表：年报 4.3%，季报和半年报 1.4%。300 只抽样股票里 89 只至少有一期。
2. 原因有两层：
   - Tushare 把同一报告期的各个版本（原始、更正、追溯调整）都挂在原始 ann_date 下，只用 f_ann_date（实际公告日）区分；前视行里约 70% 的原始版在 Tushare 已经没有了。
   - lake 拉取时没要 f_ann_date / update_flag，按 (ts_code, end_date, ann_date) 去重留第一行。多版本的期里，接口约 7 成先返回新版，于是 lake 留了新版。
3. update_flag 区分不了版本，f_ann_date 可以。用 X13 的 75 份年报 PDF（原始公告）检验：lake 与 PDF 不一致的 4 份，f_ann_date 规则全部认出，0 漏判、0 误报；原始版还在时，它与 PDF 100% 一致。
4. 对冻结基本面特征的影响（估计）：参考臂 20d 可评估行里，**2.0%** 的行至少有一个基本面特征和 PIT 口径不同（按股票自助法 90% 区间 1.1%–3.0%），集中在约 9% 的股票上。其中真正改值的 0.9%，只是变空或回退到上一期的 1.1%。这些行对模型和回测结论有多大影响，不重跑就不知道。
5. T-038 估的「8–10% 的公司年度」偏高：那里把 3 份「公告日对不上被剔除」的也算进去了，这 3 份不是重述（见下）。
6. 提议：每个版本从它的 f_ann_date 起可用（不是「每期保留最早版本」）。是否重拉、重建、重跑，由用户决定。

## 派生字段 fcff、free_cashflow：可复现性问题，不是时点问题
- 这两个是 Tushare 自己算的字段，同一期 flag 0/1 两行经常不同，又没有日期：
  - fina_indicator 的 fcff：多行的期里 37% 不同，相对差中位 15%，90 分位 209%；
  - cashflow 的 free_cashflow：65% 不同（多数是一行有值一行空）。
- lake 取的是 6 月那次接口先返回的一行。今天再拉，先返回的已经换了一行的：fcff 7%，free_cashflow 22%。也就是说，**同一脚本今天重建 lake，`fcf_yield` 会有一部分值变掉**。
- `fcf_yield`（fcff / 总市值）是 F2 的特征；`fcf_yield_cf` 用 n_cashflow_act − c_paid_invest，不受影响。
- 所以版本判定里不算这两个字段，单独统计。

## fina_indicator
- 没有 f_ann_date。按特征用到的字段（不含 fcff）、保留两位小数判版本，2.1% 的期有两个版本。多数是 2026 年中报两行的末位差，或单季字段一行为空，是 Tushare 重算，分不出先后。

## PIT 规则 v1（定稿，重建时照此实现）
- 输入：`data/lake_pit/{income,balancesheet,cashflow,fina_indicator}.parquet`，接口返回的全部行，不去重。
- 「整行内容」：除 `_row`、`_fetched_at` 以外的全部字段，按拉取字段的固定顺序，各自转成字符串（空值为空串，数值用 Python `repr(float)`）后用 `|` 连接；按这个字符串的字典序排序。只为确定，不代表优先级。
1. 三大表：每一行从它的 f_ann_date 起可用。某日 d 只看 f_ann_date ≤ d 的行，同一 (ts_code, end_date) 取 f_ann_date 最大的；同一 f_ann_date 有多行时，按整行内容排序取第一行（数值相同的并列，取哪行结果都一样）。
2. 原始版找不到的期（只有 f_ann_date > ann_date 的行）：就是第 1 条的自然结果，f_ann_date 之前看不到这一期，构建器回退到上一期，或者 TTM 为空。不另做补救。
3. fina_indicator：
   - 每一行先定可用日：与同期三大表的行对账（debt_to_assets ↔ 100 × total_liab / total_assets，netprofit_margin ↔ 100 × n_income / revenue，容差 0.01），对上的报表行里取最早的 f_ann_date；都对不上就用这一行的 ann_date；
   - 某日 d 只看可用日 ≤ d 的行，同一 (ts_code, end_date) 按 (ann_date 升序, 整行内容) 排序，取第一行（用户定的取法）；
   - 对账借日期是本卡上面提议的第 3 条，作用是让「只和重述后报表对得上」的 fina 行也按严格处理，与第 2 条一致。
4. fcff 跟着第 3 条选中的那一行走，不再依赖接口返回顺序。
