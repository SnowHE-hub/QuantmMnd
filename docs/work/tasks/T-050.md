# T-050 · A2（公告事件）的准确度：校验器 v2 与引文规则

- 起因：T-040 第一次运行中，A2 的已核实占比只有 77.7%（A1 93.2%、A3 93.4%、A4 87.9%）。
- 分支：`t/035-line-a-v2-p0`，不推送。

## 诊断（2026-10-23 晚，试跑 40 个案例的 A2 输出）
- 不一致 127 条，大部分是"引文在证据里找不到"。逐条看下来有两种：
  1. 引文与原文只差全角半角、空白，或者用"……"省略了中间部分。这是**校验器过严**；
  2. Agent 把字段摘要写进了 quote（例如"state=terminated；evidence_ids=[…]"）。这是 **Agent 用错了字段**。
- 无法核实 63 条：引用的是公告正文段落，字段名是 Agent 自己起的（段落记录没有字段），而数字其实就在段落原文里。这是**校验器的局限**。

## 改动
1. 校验器 v2（`verifier.py`）：
   - 引文比对先做 NFKC 规范化（全角转半角）、去掉空白、统一引号；
   - 引文里有省略号时，拆成几段，要求各段按顺序出现；
   - 字段在记录里不存在、而记录有原文时，到原文里找这个数（允许千分位和万、亿换算）。数不对仍判不一致。
2. 提示词通用规则第 11 条（`roles.COMMON_RULES`）：quote 只能逐字摘录原文；引用结构化字段用 field / value，不把字段名、状态、编号写进 quote。

## 补充（2026-10-23 21:xx）：正文数字的两处修正
1. **千分位**：正文数字溯源之前，先把千分位合并成一个数。之前"493,409,957.55"被拆成 493、409、957.55，试跑里 1,204 条"无出处数字"的备注几乎都是这个误报，修正后剩 425 条。
   - 剩下的多数仍不是错误：日期片段、工具参数（如"730 天窗口"）、自己算出的中值、另一条没被引用的记录里的数。
   - 所以"无出处数字"仍只作备注，不改变状态。
2. **数量级错误**（新增，改变状态）：正文里没有任何地方正确写出本条的数值，却有一个数与它只差 10 的整数次方，就判为不一致。
   - 起因：X7 本机 9B 把 24.69 亿元写成"246.86 亿元"，数值字段是对的，所以 v1 判为已核实；
   - 离线验证：DeepSeek 试跑的 160 个角色文件里误报 0 条；本机 9B 的 5 个文件里查出 5 条，逐条看都是真错；
   - 第一版规则在 DeepSeek 输出里误报了 4 条（同一句里碰巧有相差 10 倍的两个不同数字），所以改成"正确数值不在正文里才判"。这是看过结果之后的调整，如实记录。
