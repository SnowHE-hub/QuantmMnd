# T-056 · Agent 大脑（编排层 A0）

- 用户 2026-10-24："选股系统的编排器做了吗……我希望给我的选股系统加上一层 agent 大脑"。
- 分支 `t/035-line-a-v2-p0`，不推送。

## 现状：编排器原来是什么
- 方案第 7.1 节"外层确定、内层受约束"：
  - 外层：`scripts/line_a/daily_shadow.sh` + `quantmind/line_a/pipeline.py` + SQLite 任务表（`jobs.sqlite`，幂等任务键、租约），按固定顺序跑完 数据 → F0–F5 → 账本 → 研究；
  - 内层：每个研究角色在受约束的工具循环里自己决定读什么（`harness/loop.py`）。
- 缺的一层：没有一个 Agent 看全局、决定"今天最该关注什么、明天研究谁"。

## 设计（2026-10-24 实现，`quantmind/line_a/brain.py`）
- **运行时机**：每天研究和正式计划之后，正式日报生成之前（`formal --with-brain`）。
- **工具**（全部只读，每个结果带 evidence_id）：
  - market_state、formal_plan、bypass_events；
  - research_summary(ticker)、risk_card(ticker)、announcements(ticker)、event_chains(ticker)。
  - 预算：30 次工具调用、20 步、30 分钟，思考 high；DeepSeek，约 ¥0.05–0.3 / 天。
- **研究权**（真正的控制权）：
  - research_requests 最多 5 只；
  - 第二天 F6 选研究对象时作为 `brain_request` 类别优先排进（在"持仓 × 重大事件"之后）。
- **投资权不变**（方案原则 P3：研究权与投资权分开）：
  - 大脑只能给正式组合里的股票打标记：caution、avoid_new_buy、review_holding；
  - 标记显示在正式日报里，不改变持仓和委托。
- **代码核对**：
  - 标记的股票必须在正式组合（持仓或委托）里；
  - 证据编号必须是本次工具返回过的；
  - 理由里的数至少 70% 能在所引证据的记录里找到；
  - 不合格的标记剔除并记录在 `brain_run.json`。
- **台账**：`data/line_a_v2/brain/flags_ledger.jsonl`，每条标记一行，前瞻评估用。

## 第一次运行（2026-10-23 数据）

- 发现并改正的三个问题：

  2. 工具预算 16 次不够，没查完公告：改为 30 次；
  3. 理由里的数字没有核对：加了 70% 规则。

## 前瞻评估登记（在积累数据之前）
- 问题：大脑的标记有没有信息量？
- 做法：
  - 每个标记日，比较被标记股票与同一天同一资金档里未被标记的持仓或买入标的，未来 20 个交易日的收益和最大回撤，逐日配对；
  - 结果按 caution、avoid_new_buy 分开看。
- 时点：积累 ≥ 60 条标记且 ≥ 40 个交易日之后，第一次判定。
- **判定**：
  - avoid_new_buy 标的的未来 20 日平均收益比同日未标记标的低，配对差的 95% 区间上界 < 0；
  - 满足才考虑登记一个挑战臂"正式组合去掉 avoid_new_buy"，走 X9 的非劣流程；
  - 在此之前，大脑不改变任何持仓。
