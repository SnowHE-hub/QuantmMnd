## 背景与证据（[实测]，GitHub 公开 API，2026-09-24）
- 64 次运行**全部失败，从未成功**：push 47、schedule 16、pull_request 1；最早 2026-05-24（CI 加入当天），最晚 2026-09-13
- **每一次运行里 "Unit Tests" job 都失败**（失败步骤：`Run unit tests (exclude integration)`）；定时运行里 integration job 也失败
- 工作流当前状态：**Disabled**（GitHub 对长期无活动仓库的定时工作流会自动停用）
- 本地默认套件是 1130 passed / 2 failed，所以 CI 的失败**不只是**那 2 个测试：
  CI 只装 `pip install -e ".[dev]"`，且命令行 `-m "not integration"` 覆盖了 pyproject 的默认 marker 过滤，
  会选中本地默认排除的 requires_optional_deps / requires_db / stale_panel_fixture 测试 [推断]
- 失败日志需要登录 GitHub 才能下载；**先在干净环境里复现**，而不是猜

## 步骤
1. 在 WSL 里建一个干净 venv，逐字照 ci.yml 执行：`pip install -e ".[dev]"`，`NO_NETWORK=1 python -m pytest tests/ -m "not integration" --tb=short -q --no-cov --timeout=120`
2. 把失败按原因分类写进"实现说明"（缺依赖 / marker 选择 / 真 bug）
3. 修 ci.yml 与 pyproject 的 marker 选择，使 CI 选中的测试集 = 本地默认测试集 − integration
4. integration job 需要有效的 `TUSHARE_TOKEN` secret（旧 token 已在 2026Q2 全部轮换作废）——**由你决定**是更新 secret 还是暂时删掉定时触发

## allowed_paths
- .github/workflows/ci.yml
- pyproject.toml（仅 `[tool.pytest.ini_options]` 的 marker 表达式）

## 不许做
- 不删除任何测试或 marker 定义

## 验收命令
1. `pytest tests/ --collect-only -q -p no:cacheprovider > /tmp/local.txt`
2. `pytest tests/ --collect-only -q -p no:cacheprovider <ci.yml unit job 的全部参数> > /tmp/ci.txt`
3. 两个集合的差集只能是带 `integration` 标记的测试（逐个核对）
4. 干净 venv 里按 ci.yml 命令运行，退出码 0
5. `git diff --stat main...t/002` 只触及 allowed_paths
6. 合并后在 GitHub 上重新启用工作流，第一次 push 运行为绿（你来确认）
