### X7：本机 Qwen3.5-9B 作为 A1 后端
- 后端：WSL 里的 Ollama 0.30.6，`qwen3.5:9b`（Ollama 官方库，Q4_K_M）。
  - 另建 `qwen3.5:9b-16k`：同一权重，只把上下文设成 16,384（方案第 9.2 节：9B 单槽位，8K 起步，16K 单独验收）；
  - 走 OpenAI 兼容接口 `/v1/chat/completions`，工具循环、Schema 校验、修复机会、限额都与 DeepSeek 相同；
  - 思考：开启。Ollama 能不能控制思考强度，先用一个案例确认，结果写进本卡。
- 墙钟上限：本机生成慢，每个角色的墙钟上限从 900 秒放宽到 1,800 秒。其他限额不变，用时单独报告。
- 判定（第 7.5 节的降级候选）。下面三条全部满足，才算"本机 9B 可以作为 A1 的降级后端"，用于 DeepSeek 不可用时（例如校园网解密 HTTPS）：
  1. 召回不低于 DeepSeek 留出集结果 5 个百分点以上（≥ 92.1%）；
  2. 有问题声明占比不高于 DeepSeek 2 个百分点以上（≤ 2.7%）；
  3. 弃答率 ≤ 10%。
  - 默认后端不因 X7 改变：DeepSeek 便宜，用户已经批准使用，又在留出集上表现好。X7 只回答本机能不能接替它。
- 同时记录：上下文是否被截断（Ollama 日志里的 truncating），显存占用，每案例用时。

### X8：单次调用与工具循环（同一模型 DeepSeek，同一证据，同一预算）
- 单次调用组：代码先用默认参数调用 A1 的四个工具，把结果作为数据一次性放进用户消息，模型不再调用工具，直接输出 JSON。
  - 工具是 financial_snapshot、forecasts_and_express、disclosure_schedule、audit_and_pledge；
  - 思考 high，Schema 和修复机会与工具循环相同。
- 工具循环组：T-037 的留出集结果（同一提示词 v2）。
- 判定：
  - 单次调用的召回比工具循环低 2 个百分点以上，或者有问题声明的占比高 1 个百分点以上，就说明工具循环对 A1 有用；
  - 否则记为"A1 用单次调用就够了"，并报告费用差别。这条结论只适用于 A1，其他角色要另测。
- 安全：单次调用没有工具，不涉及越权调用。X14 的注入用例不在这里重跑。

## 结果与变更（2026-10-23 晚）

### X8：单次调用 vs 工具循环（DeepSeek，A1 留出集 40 案例）
| 组 | 召回 | 已核实 | 有问题声明 | 弃答 | 费用 |
|---|---|---|---|---|---|
| T-037 原结果（工具循环） | 97.1% | 94.8% | 0.7% | 0 | ¥3.45 |
| 工具循环重跑（本卡基线） | 95.4% | 92.5% | 2.1% | 0 | ¥1.64 |
| **单次调用** | **96.3%** | **97.1%** | **0.5%** | 0 | ¥1.70 |
- 按登记的判定：单次调用的召回没有低 2pp 以上，有问题声明也没有高 1pp 以上 → **"A1 用单次调用就够了"**。
  - 单次调用的已核实占比还更高，有问题的声明更少；
  - 结论只适用于 A1（输入是固定的四个结构化工具），其他角色要另测。
- 工具循环重跑比 T-037 低 1.7pp，在模型随机性的范围内。

### X7 v1（Ollama 后端）：中止
- 跑了 20 个案例：18 个弃答，2 个 ok（召回 0），每个案例 143–946 秒。
- 弃答几乎全是 JSON 语法错误（缺逗号、多余内容、空回答）和漏字段。
- 原因已查明（T-048）：Ollama 0.30.6 跑 qwen3.5 时不执行 JSON Schema 约束（同一请求在 qwen2.5 上生效，在 qwen3.5 上无效）。
  - 另外 16K 上下文下 28% 放在 CPU，速度很慢。
- **这是后端问题，不是对模型能力的结论**，v1 不作判定。

### X7 v1.1 登记（2026-10-23 晚，在运行之前；相对 v1 的改动都写在这里）
- 后端改为 llama.cpp `llama-server`，加载同一份 GGUF 权重（sha256 dec52a44…）：
  - 16K 上下文、单槽位、全部层在 GPU，实测约 53 token/秒；
  - 最终输出走 JSON Schema 约束解码，工具调用走 `--jinja` 模板。
- 结构化输出层（T-048）：
  - 最终回答先严格解析，失败用 json-repair 修语法；
  - 校验不过就重问一次，本机后端这一次用 Schema 约束；
  - 漏写的 ticker、as_of 由编排器补上；
  - DeepSeek 组也用同一层。
- 思考：**关闭**。
  - 实测开启思考时，llama-server 在一个"17×23"的问题上也要 293 秒（约 2,000 个思考 token），工具循环里不可行；
  - 这是对 v1 登记"思考开启"的改动。
- 判定规则不变（召回 ≥ 92.1%，有问题声明 ≤ 2.7%，弃答 ≤ 10%）。
- 输出：`eval/x7_local_v11_heldout_20261023/`。

- 更正（2026-10-23 晚）：单次调用的费用（¥1.70）与工具循环重跑（¥1.64）相近，**不是**更便宜。
  - 之前在对话里说"费用约一半"是错的，代码注释也已改正；
  - 单次调用的好处在准确度（已核实占比更高、有问题的声明更少）和步骤更少。
- 据此 A1 在每日研究里默认单次调用（81aa99c）；X7 仍按登记用工具循环。

  - 其余与 v1.1 相同：llama-server、16K、关闭思考、结构化输出层；
  - 判定规则不变。

### X7b 登记（2026-10-23 21:0x，在运行之前）：本机 9B 用单次调用

  - X8 表明 A1 用单次调用不比工具循环差；
