## 实现

`scripts/data_pipeline/download_events.py`：
- 分块方式由接口参数限制决定（探测记录见下），每个分块一个 part 文件 + 检查点终态 done / empty / failed / truncated
- 分页：单次返回整百行时带 offset 取下一页；若下一页与已取内容完全重复（接口不支持 offset）→ truncated，
  日期区间分块自动对半拆分重取，直到单日
- `must_have` 接口（stk_limit、moneyflow）在交易日返回空表记为 failed（T-015 的教训：空返回不能当完成）
- 频率超限错误等待 65 秒后重试；续跑跳过 done / empty，重试 failed / truncated
- `--compact`：合并为 `events/<api>_20261009.parquet` + manifest（行数、日期范围、终态计数、sha256），拒绝覆盖
- 测试 `tests/test_download_events.py`（7 个）

## 接口探测记录（2026-10-11，账号 2000 积分）

| 接口 | 发现 | 分块 |
|---|---|---|
| forecast | 必须给 ann_date 或 ts_code，不支持区间 | 每自然日 |
| report_rc | 每分钟 1 次；单次上限 5,000 行（一个月的查询只返回到 9-09～9-30） | 10 天窗口 + 每次间隔 61 秒 |
| share_float | 单次上限 6,000 行，float_date 区间只返回最后一天 | 每自然日（ann_date） |
| stk_holdernumber | 单次上限 5,500 行，offset 有效 | 每月 + 分页 |
| block_trade | 单次上限 1,000 行 | 每交易日 |
| index_weight | 每月一个快照 | 指数 × 月 |
| express、suspend_d、namechange、stk_holdertrade、repurchase | 区间有效 | 每月 |

## Codex 第二轮驳回后的修复（2026-10-11 21:30）
驳回理由：分页到上限（200 页）时，如果最后一页仍是满页，旧代码记为 done；日期区间分块因此不会对半拆分，续跑也会跳过，可能永久漏行。
1. `fetch_chunk`：到页数上限且最后一页满页 → 返回 **truncated**。日期区间分块继续对半拆分重取；单日分块无法再拆，保留 truncated（非成功），续跑会重试。
2. 新测试 5 个（共 12 个通过）：offset 正常、连续满页、超过上限 → truncated；超过上限的区间拆分后一行不漏；单日分块到上限保留 truncated 且续跑重试；
   真 EOF（恰好整页后空页）/ 短页记 done、重复页记 truncated 的区分；审计函数的列出与标记。
3. 审计：新增 `--audit-page-cap`（加 `--mark` 时把页数 ≥ 200 却记为 done 的分块改记为 truncated，原记录保存在 `page_cap_audit` 字段）。
   `pages` 是该分块所有调用（含拆分后的子区间）的总页数，所以只会多列、不会漏列。
